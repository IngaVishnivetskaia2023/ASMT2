### Fundamental difference:
```
Webpack: bundles EVERYTHING before you see anything in browser
Vite:    serves files AS-IS during dev, bundles only for production
```

### Dev server — how they work:

#### Webpack:

```
Source files → Webpack bundles ALL → one big bundle → browser

src/
├── App.tsx
├── Header.tsx
├── Footer.tsx         Webpack
├── utils.ts      ───────────►  bundle.js (everything) ──► Browser
├── api.ts
└── 500 more files     Bundles ALL       Takes 30-60 seconds
                       before serving    to start dev server
```

#### Vite:

```
Source files → Vite serves DIRECTLY → browser loads what it needs

src/
├── App.tsx ──────────► Browser asks for App.tsx
├── Header.tsx ───────► Browser asks for Header.tsx (when needed)
├── Footer.tsx         (NOT bundled, served as ES modules)
├── utils.ts
├── api.ts             Instant server start
└── 500 more files     Transforms ONE file at a time on-demand
```


```
┌────────────────────┬────────────────────┬───────────────────┐
│                    │ DEV                │ PROD              │
├────────────────────┼────────────────────┼───────────────────┤
│ Static imports     │ Browser resolves   │ Bundler resolved  │
│ import { x }       │ (native ES module) │ (at build time)   │
│                    │                    │ No imports in     │
│                    │                    │ output            │
├────────────────────┼────────────────────┼───────────────────┤
│ Dynamic imports    │ Browser resolves   │ Browser resolves  │
│ import('./chunk')  │                    │ (lazy loading)    │
│                    │                    │ But bundler       │
│                    │                    │ decided chunks    │
├────────────────────┼────────────────────┼───────────────────┤
│ Who does the work  │ Browser + Vite     │ Bundler (Rollup)  │
│                    │ (on-demand)        │ (at build time)   │
└────────────────────┴────────────────────┴───────────────────┘
```

## Vite
In dev mode you see your actual source files loaded individually — that's Vite serving native ES modules. 
Browser fetches each file on demand, no bundling. 
In production after vite build — all those files get combined into a few minified chunks. 
Two completely different strategies: **dev optimized for speed of development, prod optimized for speed of delivery**.

#### DEV: Breaking down this URL:

```
http://localhost:3000/node_modules/.vite/deps/@epam_loveship.js?v=0352524a
│                    │               │    │                  │  │
│                    │               │    │                  │  └─ cache hash
│                    │               │    │                  │     (changes when
│                    │               │    │                  │      package updates)
│                    │               │    │                  │
│                    │               │    └──────────────────└─ @epam/loveship
│                    │               │       entire library
│                    │               │       pre-bundled into
│                    │               │       ONE file
│                    │               │
│                    │               └─ deps/ = pre-bundled dependencies
│                    │
│                    └─ .vite/ = Vite's cache directory
│
└─ your dev server
```

#### What Vite did with @epam/loveship:
```
BEFORE pre-bundling (what's actually in node_modules):

node_modules/@epam/loveship/
├── index.js
├── components/
│   ├── Button.js        → imports 5 internal files
│   ├── TextInput.js     → imports 8 internal files
│   ├── Checkbox.js      → imports 4 internal files
│   ├── DatePicker.js    → imports 12 internal files
│   └── ... 100+ components, each with imports
├── helpers/
│   ├── utils.js
│   └── ... 30+ files
└── ... maybe 500+ files total


AFTER pre-bundling (what Vite serves):

node_modules/.vite/deps/@epam_loveship.js    ← ONE file
                                               500+ files → 1 file
```

#### Why Vite pre-bundles this:

```
Without pre-bundling:
  Browser imports @epam/loveship
  → loveship imports 50 internal modules
  → those import 200 more
  → those import 250 more
  = 500+ HTTP requests just for ONE library 💀

With pre-bundling:
  Browser imports @epam_loveship.js
  = 1 HTTP request ✅
```

#### ?v=0352524a — cache busting:

```
Vite generates hash based on package version + content:

First install:    @epam_loveship.js?v=0352524a
Update loveship:  @epam_loveship.js?v=8f3a1b2c  ← new hash
                                                   browser re-downloads

Same version:     ?v=0352524a stays same
                  browser uses cached version (304 Not Modified)
```


```
┌─────────────────────┬──────────────────────────────────────┐
│ Your source code    │ Served as individual files            │
│ /src/*.tsx          │ Native ES modules, not bundled        │
│                     │ Readable, not minified                │
├─────────────────────┼──────────────────────────────────────┤
│ Dependencies        │ Pre-bundled by esbuild into .vite/   │
│ @epam/loveship      │ 500+ files → 1 file                  │
│ react, react-dom    │ CommonJS → ESM conversion             │
│                     │ ?v=hash for cache busting             │
├─────────────────────┼──────────────────────────────────────┤
│ Why pre-bundle deps │ Too many internal files               │
│                     │ CommonJS not supported by browser     │
│                     │ 500 HTTP requests → 1 request         │
└─────────────────────┴──────────────────────────────────────┘
```
