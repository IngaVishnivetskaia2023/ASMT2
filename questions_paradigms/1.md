### Why do we need at all programming paradigms?

Programming paradigms exist to manage complexity. As applications grow, a single file becomes impossible to reason about, maintain, test, or collaborate on — human cognitive capacity is limited. Paradigms (OOP, functional, procedural) provide constraints and mental models that enforce structure, separation of concerns, and predictable code organization. These constraints enable reusability, testability, safe refactoring, and team collaboration at scale. Without them, any non-trivial application becomes unmaintainable — not because the machine cares, but because humans need boundaries to manage complexity.

### What is imperative approach?

Imperative programming describes **HOW** to do something — step-by-step instructions that mutate state, in a specific order. 
You explicitly tell the machine each operation to perform, like a recipe.

```
// Imperative: HOW to filter
const numbers = [1, 2, 3, 4, 5];
const result = [];
for (let i = 0; i < numbers.length; i++) {
  if (numbers[i] > 3) {
    result.push(numbers[i]);
  }
}

// Declarative (contrast): WHAT I want
const result = numbers.filter(n => n > 3);
```

The imperative approach controls the iteration, the condition check, and the mutation explicitly — the programmer manages all state transitions manually.

### Is procedural approach is the same as imperative?

No, but they're related. Imperative is the broad category — any code that describes step-by-step state mutations. 
Procedural is a specific style within imperative that organizes those steps into named procedures (functions/subroutines) for reuse and structure.

All procedural code is imperative, but not all imperative code is procedural — you can write imperative code as one flat sequence without any function organization (like a raw script). Procedural adds the concept of breaking imperative logic into callable, reusable units. 
Think of it as: imperative = "step by step", procedural = "step by step, organized into named procedures."

### Which FE frameworks are declarative vs imperative

**Declarative:** React, Vue, Angular, Svelte — you describe what the UI should look like for a given state, and the framework handles how to update the DOM. You write `<div>{items.map(i => <Item />)}</div>` — not manual DOM manipulation steps.

**Imperative:** jQuery and vanilla DOM API — you explicitly command each mutation: `$('#list').append('<li>')`, `document.createElement()`, `element.classList.add()`. You manage every step of DOM transformation yourself.

The industry moved toward declarative because it eliminates manual DOM bookkeeping, reduces bugs from state/UI desynchronization, and scales better for complex UIs — the framework reconciles desired state with actual DOM for you.

### Name Pros/Cons of declarative vs imperative and where each fits in a modern React + Node.js fullstack context

**Declarative pros:** Easier to reason about (describe outcome, not steps), 
less bug-prone for complex state/UI sync, more readable and maintainable, 
enables framework optimizations (React reconciliation, memoization).

**Declarative cons:** Performance overhead (abstraction layer), less fine-grained control, 
harder to debug when abstraction leaks, learning curve for mental model shift.

**Imperative pros:** Full control, predictable performance, direct and efficient for simple sequential tasks, no abstraction overhead.

**Imperative cons:** Harder to maintain at scale, error-prone state management, more code for complex UI, difficult to reason about as complexity grows.

**Where each fits in React + Node.js:**

| Layer | Approach | Example |
| :-- | :-- | :-- |
| React components / UI | Declarative | JSX describes desired output |
| React hooks internals / refs | Imperative | ref.current.focus(), manual DOM |
| Node.js scripts / CLI tools | Imperative/Procedural | Step-by-step file processing |
| Node.js with streams/Express middleware | Declarative-ish | Compose pipeline, describe behavior |
| Database queries (SQL, ORMs) | Declarative | Describe WHAT data, not HOW to fetch |
| Build configs (Webpack, ESLint) | Declarative | Describe desired outcome |
