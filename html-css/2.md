#### Naming Conventions

```
BEM (Block Element Modifier) ⭐ Most widely used
══════════════════════════════════════════════════

  Block:     .card
  Element:   .card__title        (double underscore)
  Modifier:  .card--highlighted  (double dash)

  <div class="card card--highlighted">
    <h2 class="card__title">Hello</h2>
    <p class="card__body">Content</p>
    <button class="card__button card__button--disabled">
      Click
    </button>
  </div>

  .card { }
  .card--highlighted { }
  .card__title { }
  .card__button { }
  .card__button--disabled { }

  ✅ Flat specificity (all 0,0,1,0)
  ✅ Self-documenting relationship
  ✅ No nesting wars
  ✅ Predictable overrides


OTHER CONVENTIONS:
══════════════════

  OOCSS (Object-Oriented CSS):
  ────────────────────────────
  Separate STRUCTURE from SKIN

  .card       { padding: 16px; }         ← structure
  .card-skin  { background: white;       ← skin
                box-shadow: 0 2px 4px; }

  SMACSS (Scalable & Modular Architecture):
  ─────────────────────────────────────────
  Categories: Base, Layout, Module, State, Theme

  .l-sidebar { }       ← layout (l- prefix)
  .is-active { }       ← state  (is- prefix)
  .theme-dark { }      ← theme

  ITCSS (Inverted Triangle CSS):
  ──────────────────────────────
  Layers from generic → specific

       Settings    ← variables, tokens
      Tools        ← mixins, functions
     Generic       ← reset, normalize
    Elements       ← bare HTML (h1, p, a)
   Objects         ← layout patterns (.container)
  Components       ← UI components (.card, .btn)
 Utilities         ← overrides (.hidden, .mt-4)

  Specificity increases as you go DOWN ▼
```

### Advanced Layout, Stacking Contexts, Positioning, Overflow

#### Stacking Context — The Most Misunderstood CSS Concept

```
WHAT CREATES A NEW STACKING CONTEXT:
═════════════════════════════════════

┌──────────────────────────────────────────────────────────┐
│                                                          │
│  ✅ position: relative/absolute/fixed + z-index ≠ auto  │
│  ✅ opacity < 1                                         │
│  ✅ transform (any value)                               │
│  ✅ filter (any value)                                  │
│  ✅ backdrop-filter                                     │
│  ✅ perspective                                         │
│  ✅ clip-path                                           │
│  ✅ mask / mask-image                                   │
│  ✅ mix-blend-mode                                      │
│  ✅ isolation: isolate            ← explicit creation   │
│  ✅ will-change (transform, opacity, etc.)              │
│  ✅ contain: layout / paint / strict                    │
│  ✅ position: fixed / sticky                            │
│  ✅ flex/grid child with z-index ≠ auto                 │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

```
THE TRAP — z-index doesn't work "globally":
════════════════════════════════════════════

  <div class="parent-A" style="position: relative; z-index: 1;">
    <div class="child" style="position: relative; z-index: 9999;">
      I CANNOT escape parent-A's stacking context!
    </div>
  </div>

  <div class="parent-B" style="position: relative; z-index: 2;">
    I will ALWAYS be above child, despite z-index: 9999
  </div>

  Visual stacking (bottom to top):
  ┌─────────────────────────────────┐
  │  parent-B (z:2)          TOP   │ ← Wins!
  ├─────────────────────────────────┤
  │  parent-A (z:1)                │
  │    └── child (z:9999)          │ ← Trapped inside z:1
  ├─────────────────────────────────┤
  │  Root stacking context  BOTTOM │
  └─────────────────────────────────┘

  z-index:9999 only matters WITHIN parent-A's context
  parent-A vs parent-B comparison: 1 < 2, parent-B wins


FIX: Use isolation: isolate
═══════════════════════════

  .modal-overlay {
    isolation: isolate;  /* Creates stacking context */
    z-index: 100;        /* Without side effects */
  }
  
  /* isolation: isolate is the CLEANEST way to create
     a stacking context — no side effects like
     transform: translateZ(0) or opacity: 0.999 */
```

#### Positioning Deep Dive
```
┌──────────────┬───────────────────────────────────────────┐
│ POSITION     │ BEHAVIOR                                  │
├──────────────┼───────────────────────────────────────────┤
│              │                                           │
│ static       │ DEFAULT — normal document flow            │
│              │ top/left/z-index IGNORED                  │
│              │ No stacking context                       │
│              │                                           │
│ relative     │ Stays in flow (space preserved)           │
│              │ Offsets FROM its normal position           │
│              │ Creates stacking context IF z-index set   │
│              │ Reference point for absolute children     │
│              │                                           │
│ absolute     │ REMOVED from flow (no space)              │
│              │ Positions relative to NEAREST positioned  │
│              │ ancestor (not static)                     │
│              │ If none → relative to <html>              │
│              │                                           │
│ fixed        │ REMOVED from flow                         │
│              │ Positions relative to VIEWPORT             │
│              │ ⚠️ UNLESS ancestor has transform/filter!   │
│              │    Then positions relative to THAT ancestor│
│              │ Always creates stacking context            │
│              │                                           │
│ sticky       │ Hybrid: relative UNTIL scroll threshold   │
│              │ Then becomes fixed WITHIN its parent       │
│              │ ⚠️ Parent MUST have scrollable overflow    │
│              │ ⚠️ Won't work if ancestor has overflow:    │
│              │    hidden/auto/scroll (common trap!)       │
│              │ Always creates stacking context            │
│              │                                           │
└──────────────┴───────────────────────────────────────────┘
```

```
FIXED POSITIONING TRAP:
═══════════════════════

  <div style="transform: scale(1);">    ← creates containing block!
    <div style="position: fixed;         ← NO LONGER relative
                top: 0; left: 0;">          to viewport!
      This modal is BROKEN — it's 
      fixed to the transformed parent,
      not the viewport! 💥
    </div>
  </div>

  Properties that break fixed positioning:
  ❌ transform (any value, even translateZ(0))
  ❌ filter
  ❌ backdrop-filter
  ❌ perspective
  ❌ contain: paint
  ❌ will-change: transform


STICKY POSITIONING TRAP:
════════════════════════

  <div style="overflow: hidden;">     ← kills sticky!
    <div style="overflow: auto; height: 500px;">
      <header style="position: sticky; top: 0;">
        Won't stick! ❌
        Nearest scroll container has overflow:hidden ancestor
      </header>
    </div>
  </div>
```

### Overflow Control

```
┌──────────────────┬──────────────────────────────────────┐
│ OVERFLOW VALUE   │ BEHAVIOR                             │
├──────────────────┼──────────────────────────────────────┤
│ visible          │ DEFAULT — content spills out         │
│ (default)        │ No scrollbars, no clipping           │
│                  │                                      │
│ hidden           │ Clips content, NO scrollbar          │
│                  │ Creates Block Formatting Context     │
│                  │ ⚠️ Kills sticky children!            │
│                  │                                      │
│ scroll           │ ALWAYS shows scrollbar               │
│                  │ Even if content fits                  │
│                  │ Creates BFC                          │
│                  │                                      │
│ auto             │ Scrollbar only WHEN needed ⭐         │
│                  │ Creates BFC                          │
│                  │                                      │
│ clip             │ Like hidden but NO scroll container  │
│                  │ overflow-clip-margin supported        │
│                  │ Does NOT kill sticky! ✅              │
│                  │ Modern alternative to hidden          │
└──────────────────┴──────────────────────────────────────┘

overflow-x / overflow-y can be set independently:
  overflow-x: auto;     ← horizontal scroll when needed
  overflow-y: hidden;   ← clip vertical


TEXT OVERFLOW:
═════════════

/* Single line truncation */
.truncate {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}

/* Multi-line truncation (3 lines) */
.line-clamp-3 {
  display: -webkit-box;
  -webkit-line-clamp: 3;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```


### Block Formatting Context (BFC)

```
WHAT CREATES BFC:
═════════════════

  overflow: hidden | auto | scroll
  display: flow-root         ← explicit, cleanest ⭐
  display: flex | grid
  float: left | right
  position: absolute | fixed
  contain: layout | paint

WHY BFC MATTERS:
════════════════

  1. Contains floats (old but still relevant)
  2. Prevents margin collapse
  3. Excludes external floats

  /* Margin collapse problem: */
  <div class="parent">
    <div class="child" style="margin-top: 20px;">
      Margin ESCAPES parent! 💥
    </div>
  </div>

  /* Fix with BFC: */
  .parent {
    display: flow-root;  /* Creates BFC — contains margins */
  }
```

#### Theme Switching Implementation

```
/* CSS */
:root { color-scheme: light dark; }

[data-theme="light"] { --color-bg: white; --color-text: #333; }
[data-theme="dark"]  { --color-bg: #1a1a1a; --color-text: #eee; }

/* Respect OS preference as default */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme]) {
    --color-bg: #1a1a1a;
    --color-text: #eee;
  }
}
```

```
// React
function ThemeToggle() {
  const toggle = () => {
    const current = document.documentElement.dataset.theme;
    const next = current === 'dark' ? 'light' : 'dark';
    document.documentElement.dataset.theme = next;
    localStorage.setItem('theme', next);
  };

  return <button onClick={toggle}>Toggle Theme</button>;
}

// On app load:
const saved = localStorage.getItem('theme');
if (saved) document.documentElement.dataset.theme = saved;
```

```
HOW IT WORKS:
═════════════

  <html data-theme="light">     ←── JS toggles this attribute
    <body>
      <div class="card">        ←── reads var(--card-bg)
                                      ↓ which reads var(--color-bg-primary)
                                        ↓ which reads var(--white) = #FFFFFF
                                        
  Toggle to dark:
  
  <html data-theme="dark">      ←── attribute changes
    <body>
      <div class="card">        ←── SAME CSS, SAME vars
                                      ↓ var(--color-bg-primary)
                                        ↓ NOW reads var(--gray-800) = #343A40

  🔥 ZERO JavaScript style manipulation
  🔥 ZERO re-render needed
  🔥 Browser handles ALL repainting
  🔥 Instant theme switch
```

## Performance, Maintainability & Cross-Browser

#### CSS Performance Optimization
```
RENDERING PIPELINE:
═══════════════════

  Style → Layout → Paint → Composite
  
  ┌────────┐  ┌────────┐  ┌───────┐  ┌───────────┐
  │ STYLE  │→ │ LAYOUT │→ │ PAINT │→ │ COMPOSITE │
  │ calc   │  │ reflow │  │repaint│  │  GPU      │
  │ rules  │  │ size & │  │ pixels│  │  layers   │
  │        │  │ position│  │       │  │           │
  └────────┘  └────────┘  └───────┘  └───────────┘
  
  COST: ◄──── EXPENSIVE ─────── CHEAP ────►


WHICH PROPERTIES TRIGGER WHAT:
══════════════════════════════

  Layout (EXPENSIVE 🔴):
  ──────────────────────
  width, height, padding, margin, 
  border-width, display, position,
  top, left, right, bottom, font-size,
  float, text-align, overflow, font-family
  
  → Triggers: Layout + Paint + Composite
  → ALL downstream elements recalculated

  
  Paint Only (MODERATE 🟡):
  ─────────────────────────
  color, background, border-color,
  border-style, border-radius, outline,
  box-shadow, text-decoration, visibility
  
  → Triggers: Paint + Composite
  → No geometry recalculation

  
  Composite Only (CHEAP 🟢):
  ──────────────────────────
  transform, opacity, filter,
  will-change, backface-visibility
  
  → Triggers: Composite ONLY
  → GPU handles it, no main thread!
```

```
/* ═══ PERFORMANCE BEST PRACTICES ═══ */

/* 🔴 BAD — triggers layout on every frame */
.animate-bad {
  transition: left 0.3s, top 0.3s, width 0.3s;
}

/* 🟢 GOOD — composite only, GPU accelerated */
.animate-good {
  transition: transform 0.3s, opacity 0.3s;
}

/* 🔴 BAD — moving element with left/top */
@keyframes slide-bad {
  from { left: 0; }
  to { left: 200px; }
}

/* 🟢 GOOD — using transform */
@keyframes slide-good {
  from { transform: translateX(0); }
  to { transform: translateX(200px); }
}


/* ═══ will-change — use sparingly ═══ */

/* Hint browser to prepare GPU layer */
.card:hover {
  will-change: transform;  /* prepare on hover */
}
.card:active {
  transform: scale(0.98);   /* animate on click */
}

/* ⚠️ DON'T do this — creates GPU layers for EVERYTHING */
* { will-change: transform; }  /* ❌ Memory explosion */


/* ═══ contain — limit browser recalculation scope ═══ */

.card {
  contain: layout style;  
  /* Browser knows: changes inside .card 
     CANNOT affect outside elements
     → Limits reflow scope → Faster */
}

.widget {
  contain: strict;  
  /* layout + style + size + paint
     Most aggressive containment
     ⚠️ Element must have explicit size */
}

/* content-visibility — skip offscreen rendering */
.card {
  content-visibility: auto;
  contain-intrinsic-size: 200px;
  /* Browser skips rendering if offscreen
     MASSIVE performance for long lists */
}
```


#### Selector Performance
```
SELECTOR EFFICIENCY (fast → slow):
══════════════════════════════════

  ✅ #id               ← fastest (hash lookup)
  ✅ .class             ← very fast (hash lookup)
  ✅ tag                ← fast (hash lookup)
  ⚠️ .parent .child     ← evaluated RIGHT to LEFT!
  ❌ div > p > span     ← multiple ancestor checks
  ❌ [attr="value"]     ← attribute scan
  ❌ :nth-child(2n+1)  ← calculation needed
  ❌ *                  ← matches EVERYTHING

  ⚠️ Browser reads selectors RIGHT TO LEFT:

  .header .nav .link span { }
                       ^^^^
                       starts HERE
                       
  1. Find ALL <span> elements
  2. Check if parent matches .link
  3. Check if ancestor matches .nav
  4. Check if ancestor matches .header

  BEM avoids this by keeping selectors FLAT:
  .header__nav-link-text { }  ← ONE class lookup, done ✅


  IN PRACTICE:
  ════════════
  Selector performance rarely matters with modern browsers
  UNLESS you have 10,000+ elements or very complex selectors
  
  Focus on:
  ✅ Reducing total CSS size (unused removal)
  ✅ Avoiding expensive properties in animations
  ✅ Using contain/content-visibility for long lists
```

#### Critical CSS & Loading Optimization

```
RENDER-BLOCKING CSS PROBLEM:
════════════════════════════

  Browser downloads HTML
       │
       ├── Finds <link rel="stylesheet" href="all.css">
       │        │
       │        ▼
       │   Downloads 150KB CSS file ← BLOCKS RENDERING!
       │        │
       │        ▼
       │   Parses entire CSS → CSSOM
       │        │
       ▼        ▼
  First Paint (delayed!) 😡


CRITICAL CSS SOLUTION:
══════════════════════

  <head>
    <!-- Inline critical (above-the-fold) CSS -->
    <style>
      .header { ... }
      .hero { ... }
      .nav { ... }
      /* Only what's needed for first screen */
    </style>
    
    <!-- Load rest asynchronously -->
    <link rel="preload" href="full.css" as="style" 
          onload="this.rel='stylesheet'">
    <noscript>
      <link rel="stylesheet" href="full.css">
    </noscript>
  </head>

  Result:
  ┌────────────┐
  │ Inline CSS │ → Instant first paint ✅
  │ (2KB)      │
  └────────────┘
  ┌────────────┐
  │ full.css   │ → Loads in background, non-blocking
  │ (150KB)    │
  └────────────┘
```
