```
myapp.com → DNS → TCP → TLS → HTTP → CloudFront → S3 → 
→ HTML → CSS → JS → DOM → CSSOM → Render Tree → Paint → 
→ React mount → Event Listeners → Интерактивное приложение
```


#### Фаза 1: DNS — превращение домена в IP
```
Пользователь вводит: myapp.com + Enter

Браузер: "Мне нужен IP адрес для myapp.com"

Шаг 1.1: Кеш браузера
────────────────────────
  Браузер проверяет свой кеш DNS.
  Был недавно на myapp.com? → IP уже есть → пропускаем DNS.
  Нет? → идём дальше.

Шаг 1.2: Кеш ОС
────────────────────────
  ОС проверяет свой DNS кеш + файл /etc/hosts.
  Нет? → идём дальше.

Шаг 1.3: DNS Resolver провайдера (или 8.8.8.8)
────────────────────────────────────────────────

  Браузер                   DNS Resolver             Root DNS        .com DNS       Route 53
  (UDP socket)              (провайдер)              (мировые)       (VeriSign)     (AWS)
       │                         │                      │               │              │
       │── "myapp.com?" ──→      │                      │               │              │
       │      UDP:53             │── "myapp.com?" ──→   │               │              │
       │                         │                 ←── "спроси .com"    │              │
       │                         │── "myapp.com?" ─────────────────→    │              │
       │                         │                                 ←── "спроси         │
       │                         │                                      ns-xxx.        │
       │                         │                                      awsdns.com"    │
       │                         │──   "myapp.com?" ────────────────────────────────→  │
       │                         │                                                 ←── │
       │                         │                         IP: 13.224.50.12            │
       │                         │                         (CloudFront IP)             │
       │  ←── 13.224.50.12 ────  │                                                     │
       │                                                                               │


  Route 53 (AWS DNS сервис) отвечает IP адресом CloudFront,
  НЕ IP адресом S3 напрямую.
  
  Результат: myapp.com → 13.224.50.12 (CloudFront edge server)
  
  Время: 20-100ms (если не закеширован)
  Протокол: UDP socket, порт 53
```

#### Фаза 2: TCP + TLS — установка соединения

```
Браузер знает IP. Теперь нужно установить соединение.

Шаг 2.1: TCP Handshake (3 пакета)
───────────────────────────────────

  Браузер                          CloudFront Edge Server
  84.15.22.78                      13.224.50.12:443
       │                                │
       │── SYN ──────────────────────→  │    "Хочу подключиться"
       │                                │
       │←── SYN-ACK ──────────────────  │    "Ок, подключайся"
       │                                │
       │── ACK ──────────────────────→  │    "Подключился"
       │                                │
       TCP соединение установлено.
       Время: 1 RTT (Round Trip Time)
       ~10-50ms до ближайшего CloudFront edge


Шаг 2.2: TLS Handshake (HTTPS)
────────────────────────────────

  Браузер                          CloudFront
       │                                │
       │── ClientHello ──────────────→  │  "Я умею TLS 1.3,
       │   (поддерживаемые шифры,       │   вот мои шифры,
       │    SNI: myapp.com)             │   я хочу myapp.com"
       │                                │
       │←── ServerHello ──────────────  │  "Выбрал шифр X,
       │    Certificate                 │   вот мой сертификат,
       │    (myapp.com *.pem)           │   вот ключ"
       │                                │
       │  Браузер проверяет:            │
       │  - Сертификат валиден? ✅      │
       │  - Выдан для myapp.com? ✅     │
       │  - Не истёк? ✅                │
       │  - Доверенный CA? ✅           │
       │                                │
       │── Finished ─────────────────→  │
       │←── Finished ─────────────────  │
       │                                │
       🔒 Шифрованный канал установлен.
       Время: 1 RTT (TLS 1.3)
       
  Итого TCP + TLS: 2 RTT (~20-100ms)
```

#### Фаза 4: HTTP/2 ответ — ресурсы летят в браузер

```
Шаг 4.1: CloudFront отвечает с index.html
──────────────────────────────────────────

  CloudFront → Браузер:
  
    :status: 200
    content-type: text/html
    content-encoding: br                  (brotli сжатие)
    cache-control: no-cache               (HTML всегда проверяй)

    <!DOCTYPE html>
    <html>
    <head>
      <meta charset="utf-8">
      <title>My App</title>
      <link rel="stylesheet" href="/static/css/main.a1b2c3.css">
      <link rel="stylesheet" href="/static/css/vendor.d4e5f6.css">
    </head>
    <body>
      <div id="root"></div>                ← ПУСТОЙ! React будет рендерить сюда
      <script src="/static/js/vendor.j0k1l2.js"></script>
      <script src="/static/js/main.g7h8i9.js"></script>
    </body>
    </html>

  Размер: ~1-2KB (gzip/brotli)
  Время: первый байт через 50-200ms


Шаг 4.2: HTTP/2 Multiplexing — параллельная загрузка
─────────────────────────────────────────────────────

  Браузер парсит HTML, находит ресурсы, запрашивает ВСЕ СРАЗУ.
  HTTP/2: одно TCP соединение, много потоков параллельно.

  ┌─── ОДНО TCP соединение к CloudFront ─────────────────────┐
  │                                                           │
  │  Stream 1: GET /static/css/main.a1b2c3.css                │
  │  Stream 2: GET /static/css/vendor.d4e5f6.css              │
  │  Stream 3: GET /static/js/vendor.j0k1l2.js                │
  │  Stream 4: GET /static/js/main.g7h8i9.js                  │
  │  Stream 5: GET /favicon.ico                               │
  │                                                           │
  │  Все запросы отправлены ОДНОВРЕМЕННО.                     │
  │  НЕ ждём завершения одного чтобы начать другой.           │
  │  HTTP/1.1: 6 соединений макс, по одному запросу каждое.   │
  │  HTTP/2: 1 соединение, сотни потоков.                     │
  │                                                           │
  │  Ответы приходят ЧЕРЕДУЯСЬ:                               │
  │                                                           │
  │  ←── chunk css/main (stream 1)                            │
  │  ←── chunk js/vendor (stream 3)                           │
  │  ←── chunk css/vendor (stream 2)                          │
  │  ←── chunk js/vendor (stream 3)                           │
  │  ←── chunk js/main (stream 4)                             │
  │  ←── favicon.ico complete (stream 5)                      │
  │  ←── css/main complete (stream 1)                         │
  │  ←── css/vendor complete (stream 2)                       │
  │  ←── chunk js/vendor (stream 3)                           │
  │  ←── js/main complete (stream 4)                          │
  │  ←── js/vendor complete (stream 3)                        │
  │                                                           │
  └───────────────────────────────────────────────────────────┘

  CloudFront cache-control для static assets:
    cache-control: public, max-age=31536000, immutable
    (кешируй на год — имя файла содержит хеш,
     при изменении файла хеш меняется → новый URL)
```

#### Фаза 5: Critical Rendering Path
```
═══════════════════════════════════════════════════════════════
  Байты → Символы → Токены → Ноды → DOM/CSSOM → Render → Paint
═══════════════════════════════════════════════════════════════


Шаг 5.1: Парсинг HTML → DOM (Document Object Model)
─────────────────────────────────────────────────────

  HTML байты прибывают через TCP socket (Stream):

  Bytes:  3C 21 44 4F 43 54 59 50 45 ...
            ↓ decode (UTF-8)
  Chars:  < ! D O C T Y P E   h t m l >
            ↓ tokenize
  Tokens: [DOCTYPE] [StartTag html] [StartTag head] [StartTag meta] ...
            ↓ build tree
  DOM:
            document
              │
              html
              ├── head
              │   ├── meta (charset)
              │   ├── title → "My App"
              │   ├── link (css/main.a1b2c3.css)     ← обнаружен CSS!
              │   └── link (css/vendor.d4e5f6.css)    ← обнаружен CSS!
              └── body
                  ├── div#root                         ← пустой
                  ├── script (js/vendor.j0k1l2.js)    ← обнаружен JS!
                  └── script (js/main.g7h8i9.js)      ← обнаружен JS!

  Парсинг ПОТОКОВЫЙ (streaming):
  Браузер НЕ ждёт весь HTML. Парсит по мере получения.
  Как только видит <link> или <script> → начинает загрузку.
  

Шаг 5.2: Парсинг CSS → CSSOM (CSS Object Model)
──────────────────────────────────────────────────

  CSS файлы прибывают по HTTP/2 streams:
  
  Bytes → Characters → Tokens → CSSOM tree

  CSSOM:
    body
    ├── font-family: Inter
    ├── margin: 0
    │
    .header
    ├── background: #1a1a2e
    ├── height: 64px
    │
    .button
    ├── background: #0066ff
    ├── border-radius: 8px
    ├── padding: 12px 24px
    ...

  ⚠️  CSS — RENDER BLOCKING.
  Браузер НЕ отрисует ничего пока ВЕСЬ CSS не загружен и распарсен.
  Почему: без CSS будет "вспышка" нестилизованного контента (FOUC).


Шаг 5.3: JavaScript — PARSER BLOCKING
───────────────────────────────────────

  Браузер встречает <script src="vendor.js">:
  
  ⚠️  ОСТАНАВЛИВАЕТ парсинг HTML.
  Почему: JS может вызвать document.write() и изменить HTML.
  Браузер не знает заранее что делает скрипт → ждёт.

  Timeline:
  
  HTML парсинг: ████████████|STOP|
  CSS загрузка:   ████████████████
  JS загрузка:      ████████████████████
  JS выполнение:                        |████████|
  HTML парсинг:                                    |████| (продолжил)

  Чтобы НЕ блокировать:
  <script src="main.js" defer></script>
  
  С defer:
  HTML парсинг: ██████████████████████████████████████
  CSS загрузка:   ████████████████
  JS загрузка:      ████████████████████  (параллельно!)
  JS выполнение:                                     |████████| (после HTML)
```

Шаг 6.2: Layout (Reflow)
──────────────────────────

  Браузер вычисляет ГЕОМЕТРИЮ каждого элемента:
  
  div#root:
    x: 0, y: 0
    width: 1920px (viewport width)
    height: 0px (пустой!)


Шаг 6.3: Paint
────────────────

  Браузер отрисовывает пиксели:
  
  На данный момент: БЕЛЫЙ ЭКРАН (ничего нет в div#root)
  
  Это момент FCP? Нет — контента ещё нет.
  Пользователь видит пустую страницу.

#### Фаза 7: JavaScript выполняется → React монтируется

```
Шаг 7.1: vendor.js выполняется
─────────────────────────────────

  vendor.js содержит:
    ─ React runtime (createElement, hooks, reconciler, fiber)
    ─ ReactDOM (render, работа с DOM)
    ─ React Router
    ─ Другие библиотеки
  
  Всё загружается в ПАМЯТЬ (V8 heap).
  Пока ничего не рендерится.


Шаг 7.2: main.js выполняется → React монтируется
──────────────────────────────────────────────────

  main.js содержит:
  
  import { createRoot } from 'react-dom/client';
  import App from './App';
  
  const root = createRoot(document.getElementById('root'));
  root.render(<App />);
  //   ^^^^^^
  //   ВОТ ЗДЕСЬ начинается React

  
  Что делает root.render(<App />):
  
  7.2.1: React создаёт Virtual DOM (Fiber tree)
  ───────────────────────────────────────────────
  
    React вызывает App():
    
    function App() {
      const [user, setUser] = useState(null);
      
      useEffect(() => {
        fetch('/api/me').then(r => r.json()).then(setUser);
      }, []);
      
      return (
        <div className="app">
          <Header />
          <Sidebar />
          <main>
            {user ? <Dashboard user={user} /> : <Spinner />}
          </main>
        </div>
      );
    }
    
    React строит Fiber tree:
    
    FiberNode(App)
    ├── FiberNode(div.app)
    │   ├── FiberNode(Header)
    │   │   ├── FiberNode(nav)
    │   │   │   ├── FiberNode(a) → "Home"
    │   │   │   ├── FiberNode(a) → "Dashboard"
    │   │   │   └── FiberNode(a) → "Settings"
    │   │   └── FiberNode(button.logout) → "Logout"
    │   ├── FiberNode(Sidebar)
    │   │   └── ...
    │   └── FiberNode(main)
    │       └── FiberNode(Spinner)     ← user ещё null
    └── (effects queue: fetch /api/me)


  7.2.2: React коммитит Fiber tree → реальный DOM
  ─────────────────────────────────────────────────
  
    React обходит Fiber tree и вызывает DOM API:
    
    document.getElementById('root')
    
    const div = document.createElement('div');
    div.className = 'app';
    
    const nav = document.createElement('nav');
    const a1 = document.createElement('a');
    a1.textContent = 'Home';
    a1.href = '/';
    nav.appendChild(a1);
    
    const button = document.createElement('button');
    button.className = 'logout';
    button.textContent = 'Logout';
    
    ... сотни вызовов DOM API ...
    
    root.appendChild(div);
    
    
    DOM ТЕПЕРЬ:
    
    document
    └── html
        └── body
            └── div#root
                └── div.app                    ← React создал
                    ├── header                 ← React создал
                    │   └── nav
                    │       ├── a "Home"
                    │       ├── a "Dashboard"
                    │       └── a "Settings"
                    │   └── button.logout "Logout"
                    ├── aside.sidebar          ← React создал
                    │   └── ...
                    └── main
                        └── div.spinner        ← user === null
                            └── svg (animation)

```

#### Фаза 8: Event Listeners — React навешивает обработчики

```
Шаг 8.1: React НЕ навешивает listeners на каждый элемент
──────────────────────────────────────────────────────────

  Твой код:
    <button onClick={handleLogout}>Logout</button>
    <a onClick={navigateTo}>Dashboard</a>
    <input onChange={handleSearch} />

  Наивный подход (без React):
    button.addEventListener('click', handleLogout)
    a.addEventListener('click', navigateTo)
    input.addEventListener('change', handleSearch)
    // 100 элементов = 100 listeners 😱

  React подход — EVENT DELEGATION:
    Один listener на корневой элемент!

    root.addEventListener('click', reactClickHandler)
    root.addEventListener('change', reactChangeHandler)
    root.addEventListener('input', reactInputHandler)
    // ... по одному на КАЖДЫЙ ТИП события


Шаг 8.2: Как работает delegation
──────────────────────────────────

    Пользователь кликает на кнопку "Logout":
    
    Клик на <button>
      │
      ▼  Event bubbles up (всплывает):
    <button> → <header> → <div.app> → <div#root>
                                            │
                                            ▼
                                    React перехватывает
                                    на div#root
                                            │
                                            ▼
                                    React смотрит:
                                    "На каком Fiber Node
                                     произошёл клик?"
                                            │
                                            ▼
                                    FiberNode(button.logout)
                                    имеет onClick = handleLogout
                                            │
                                            ▼
                                    Вызывает handleLogout()


    ┌─── div#root ──────────────────────────────────────┐
    │                                                    │
    │   React listener: onClick (один на весь root)     │
    │                                                    │
    │   ┌── header ──────────────────────────────┐      │
    │   │   ┌── button "Logout" ──────────┐      │      │
    │   │   │  клик! → bubble up ──────────────────→ React: "ага,
    │   │   │  НЕТ addEventListener тут   │      │      │   это Fiber
    │   │   └─────────────────────────────┘      │      │   с onClick
    │   └────────────────────────────────────────┘      │   = handleLogout"
    │                                                    │
    └────────────────────────────────────────────────────┘
    
    Почему delegation:
      ─ 1 listener вместо 1000 (меньше памяти)
      ─ Новые элементы автоматически "работают"
        (не надо снимать/навешивать при ре-рендере)
```


#### Фаза 9: `useEffect` → API запрос → финальный рендер

```
Шаг 9.1: React выполняет effects ПОСЛЕ paint
──────────────────────────────────────────────

  useEffect(() => {
    fetch('/api/me')...
  }, []);
  
  Этот effect запускается ПОСЛЕ того как браузер отрисовал.
  Пользователь УЖЕ видит страницу (со Spinner).


Шаг 9.2: fetch('/api/me') → API Gateway → Lambda/Server
─────────────────────────────────────────────────────────

  Для API запросов — ВОТ ТУТ API Gateway:
  
  Браузер                CloudFront        API Gateway         Lambda/ECS
     │                       │                  │                   │
     │── GET /api/me ──→    │──────────────→   │                   │
     │                       │                  │── invoke ──────→ │
     │                       │                  │                   │ query DB
     │                       │                  │                   │ ...
     │                       │                  │ ←── response ──── │
     │                       │ ←────────────── │                   │
     │←── { name: "Anna" }── │                  │                   │
  
  
  S3:          для СТАТИКИ (HTML, CSS, JS, images)
  API Gateway: для API (/api/*)
  
  CloudFront маршрутизирует:
    /static/* → S3 origin
    /api/*    → API Gateway origin


Шаг 9.3: React ре-рендер с данными
────────────────────────────────────

  setUser({ name: "Anna" }) вызвался.
  
  React:
    1. Строит НОВЫЙ Fiber tree
    2. Сравнивает со старым (diffing/reconciliation)
    3. Находит разницу:
       Было:   <Spinner />
       Стало:  <Dashboard user={{ name: "Anna" }} />
    4. Обновляет ТОЛЬКО изменившуюся часть DOM:
    
       main.removeChild(spinnerDiv)
       main.appendChild(dashboardDiv)
       // ... создаёт все дочерние элементы Dashboard
    
  Пользователь видит Dashboard вместо Spinner.
```
