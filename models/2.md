## Login → JWT → API Gateway → Lambda → PostgreSQL

```
┌─────────┐     ┌────────────┐     ┌─────────────┐     ┌──────────┐     ┌──────────────┐     ┌─────┐
│ Браузер  │────→│ CloudFront │────→│ API Gateway │────→│  Lambda  │────→│ RDS Postgres │     │Cognito│
│ React SPA│←────│ CDN        │←────│ + Authorizer│←────│ Function │←────│ Private DB   │     │ Auth │
└─────────┘     └────────────┘     └─────────────┘     └──────────┘     └──────────────┘     └──────┘
      │                                                                                          │
      └──────────── Login / Token ──────────────────────────────────────────────────────────────→│
```

```
Ключевое:
  Никто из интернета НЕ может попасть в Lambda или RDS напрямую.

```

```
Шаг 2.2: Сетевой уровень — НОВОЕ TCP соединение
──────────────────────────────────────────────────

  ⚠️  Это ДРУГОЙ домен! cognito-idp.eu-west-1.amazonaws.com

  Браузер                          Cognito Service
  ───────                          ───────────────
  
  DNS: cognito-idp.eu-west-1.amazonaws.com → 52.xx.xx.xx
  
  TCP handshake   ──────→  (новый socket, новый fd)
  TLS handshake   ──────→
  
  POST /          ──────→  { AuthFlow, USERNAME, PASSWORD }

  Соединения браузера в этот момент:
  
  TCP #1: CloudFront (13.224.50.12:443)     ← для static + API
          Может быть ещё открыто (HTTP/2 keep-alive)
          
  TCP #2: Cognito (52.xx.xx.xx:443)         ← НОВОЕ для auth
          Другой домен → другое соединение


Шаг 2.3: Cognito проверяет credentials
────────────────────────────────────────

  │     ─ "admins"                                           │

  │                                                          │
```

#### Фаза 3: Что внутри JWT Token

```
JWT = три части, разделённые точкой:

  eyJhbGciOi... . eyJzdWIiOi... . SflKxwRJSM...
  ──────────────   ──────────────   ─────────────
     HEADER           PAYLOAD         SIGNATURE


HEADER (base64):
{
  "alg": "RS256",                    ← алгоритм подписи
  "kid": "abc123key"                 ← какой ключ Cognito использовал
}

PAYLOAD (base64) — вот где данные:
{
  "sub": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "email": "anna@example.com",
  "cognito:username": "anna",
  "cognito:groups": ["admins", "editors"],    ← ГРУППЫ!
  "iss": "https://cognito-idp.eu-west-1.amazonaws.com/eu-west-1_XYZ123",
  "aud": "abc123clientid",
  "token_use": "access",
  "iat": 1700000000,                          ← issued at
  "exp": 1700003600,                          ← expires (1 час)
  "scope": "openid profile email"
}

SIGNATURE:
  RS256(header + payload, Cognito_PRIVATE_KEY)
  Только Cognito может СОЗДАТЬ подпись.
  Любой может ПРОВЕРИТЬ используя Cognito PUBLIC KEY.


React сохраняет токены:
  localStorage.setItem('accessToken', tokens.AccessToken);
  localStorage.setItem('idToken', tokens.IdToken);
```

#### Фаза 5: API Gateway — авторизация JWT

```
Шаг 5.1: API Gateway Authorizer проверяет JWT
───────────────────────────────────────────────

  ┌─── API Gateway ──────────────────────────────────────────────────┐
  │                                                                  │
  │  Получил: GET /api/me                                            │
  │           Authorization: Bearer eyJhbGciOi...                    │
  │                                                                  │
  │  AUTHORIZER (Cognito JWT Authorizer):                            │
  │                                                                  │
  │  Шаг A: Извлечь токен из заголовка                               │
  │    token = "eyJhbGciOi..."                                       │
  │                                                                  │
  │  Шаг B: Декодировать header (без проверки подписи)               │
  │    { "kid": "abc123key" }                                        │
  │                                                                  │
  │  Шаг C: Скачать PUBLIC KEYS Cognito (JWKS)                       │
  │    GET https://cognito-idp.eu-west-1.amazonaws.com/              │
  │        eu-west-1_XYZ123/.well-known/jwks.json                    │
  │    → { keys: [{ kid: "abc123key", n: "...", e: "AQAB" }] }       │
  │    (кешируется — не скачивается каждый раз)                      │
  │                                                                  │
  │  Шаг D: Проверить ПОДПИСЬ токена                                 │
  │    RS256.verify(header + payload, signature, publicKey)          │
  │    ✅ Подпись валидна → токен создан Cognito, не подделан       │
  │                                                                  │
  │  Шаг E: Проверить CLAIMS                                         │
  │    exp > now?          ✅ не истёк                               │
  │    iss == наш pool?    ✅ правильный Cognito User Pool           │
  │    aud == наш client?  ✅ правильное приложение                  │
  │    token_use == access ✅ правильный тип токена                  │
  │                                                                   │
  │  Шаг F: Проверить ГРУППЫ (если настроено)                         │
  │    cognito:groups содержит "admins"?                              │
  │    Route GET /api/me доступен для группы "admins"? ✅            │
  │                                                                  │
  │  РЕЗУЛЬТАТ: ALLOW → передать запрос в Lambda                     │
  │                                                                  │
  │  (Если бы токен был невалиден → 401 Unauthorized)               │
  │  (Если бы группа не подходила → 403 Forbidden)                   │
  │                                                                   │
  └──────────────────────────────────────────────────────────────────┘
```

#### Фаза 6: Lambda — запуск функции

```
Шаг 6.1: API Gateway вызывает Lambda (НЕ по HTTP!)
────────────────────────────────────────────────────

  API Gateway НЕ делает HTTP запрос к Lambda.
  Вызов через ВНУТРЕННИЙ AWS API (Invoke API).

  API Gateway → AWS Lambda Service → твоя функция

  Lambda получает EVENT (не HTTP request напрямую):
  
  {
    "httpMethod": "GET",
    "path": "/api/me",
    "headers": {
      "authorization": "Bearer eyJ..."
    },
    "requestContext": {
      "authorizer": {
        "claims": {
          "sub": "a1b2c3d4-...",
          "email": "anna@example.com",
          "cognito:groups": "[admins, editors]"
        }
      }
    }
  }
  
  ☝️  API Gateway УЖЕ проверил токен и положил claims в event.
  Lambda НЕ проверяет JWT сама — доверяет API Gateway.


Шаг 6.2: Cold Start vs Warm Start
───────────────────────────────────

  ┌─── Lambda Service ─────────────────────────────────────────────┐
  │                                                                 │
  │  Получил запрос Invoke для функции "getUser"                   │
  │                                                                 │
  │  Есть ТЁПЛЫЙ контейнер?                                        │
  │                                                                 │
  │  ┌─── COLD START (контейнера нет) ──────────────────────────┐  │
  │  │                                                           │  │
  │  │  1. Создать microVM (Firecracker)           ~50ms        │  │
  │  │     Лёгкая виртуальная машина                             │  │
  │  │                                                           │  │
  │  │  2. Скачать код функции из S3               ~100ms       │  │
  │  │     getUser.zip → /var/task/                              │  │
  │  │                                                           │  │
  │  │  3. Запустить Node.js runtime               ~50ms        │  │
  │  │     /var/lang/bin/node                                    │  │
  │  │                                                           │  │
  │  │  4. Выполнить init code (вне handler)       ~100ms       │  │
  │  │     import pg from 'pg';                                  │  │
  │  │     const pool = new Pool({ ... });                       │  │
  │  │     // ← TCP соединение к RDS создаётся ЗДЕСЬ            │  │
  │  │                                                           │  │
  │  │  5. Вызвать handler(event)                  ~50ms        │  │
  │  │                                                           │  │
  │  │  Итого Cold Start: ~200-500ms                             │  │
  │  │                                                           │  │
  │  └───────────────────────────────────────────────────────────┘  │
  │                                                                 │
  │  ┌─── WARM START (контейнер ЕСТЬ) ──────────────────────────┐  │
  │  │                                                           │  │
  │  │  Контейнер уже запущен с прошлого вызова.                │  │
  │  │  Node.js процесс жив.                                    │  │
  │  │  Pool соединений к DB жив.                                │  │
  │  │                                                           │  │
  │  │  Сразу вызвать handler(event)               ~5ms         │  │
  │  │                                                           │  │
  │  │  Итого Warm Start: ~5-20ms                                │  │
  │  │                                                           │  │
  │  └───────────────────────────────────────────────────────────┘  │
  │                                                                 │
  │  AWS держит контейнер ТЁПЛЫМ ~5-15 минут после вызова.         │
  │  Если нет запросов → контейнер уничтожается.                    │
  │  Следующий запрос → снова Cold Start.                           │
  │                                                                 │
  └─────────────────────────────────────────────────────────────────┘
```

#### Фаза 7: Lambda → PostgreSQL (внутри VPC)

```
Шаг 7.1: Код Lambda функции
─────────────────────────────

  // INIT (выполняется ОДИН раз при Cold Start)
  import pg from 'pg';
  
  const pool = new pg.Pool({
    host: 'mydb.cluster-xyz.eu-west-1.rds.amazonaws.com',
    port: 5432,
    database: 'myapp',
    user: 'lambda_user',
    password: process.env.DB_PASSWORD,   // из AWS Secrets Manager
    max: 5,                               // макс 5 соединений в pool
    ssl: { rejectUnauthorized: true }
  });
  
  // HANDLER (выполняется КАЖДЫЙ вызов)
  export const handler = async (event) => {
    const userId = event.requestContext.authorizer.claims.sub;
    const groups = event.requestContext.authorizer.claims['cognito:groups'];
    
    const result = await pool.query(
      'SELECT id, email, name, avatar FROM users WHERE cognito_sub = $1',
      [userId]
    );
    
    if (result.rows.length === 0) {
      return { statusCode: 404, body: JSON.stringify({ error: 'User not found' }) };
    }
    
    return {
      statusCode: 200,
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        user: result.rows[0],
        groups: groups
      })
    };
  };


Шаг 7.2: Сетевой путь Lambda → RDS (внутри VPC)
──────────────────────────────────────────────────

  Lambda контейнер получает ENI (Elastic Network Interface)
  в Private Subnet VPC.
  
  ┌─── Private Subnet ─────────────────────────────────────────┐
  │                                                            │
  │  Lambda Container                    RDS PostgreSQL        │
  │  ┌──────────────┐                   ┌──────────────┐       │
  │  │ IP: 10.0.1.50│                   │ IP: 10.0.2.20│       │
  │  │              │   TCP Socket      │              │       │
  │  │ pg.Pool      │ ═══════════════►  │ :5432        │       │
  │  │ connect()    │   Private network  │             │       │
  │  │              │   НЕ через         │ PostgreSQL  │       │
  │  │              │   интернет!        │ engine      │       │
  │  └──────────────┘                   └──────────────┘       │
  │                                                            │
  │  Security Group Rules:                                     │
  │  Lambda SG → RDS SG: TCP:5432 ALLOW ✅                     │
  │  Internet → RDS: ❌ DENY                                   │
  │                                                             │
  └─────────────────────────────────────────────────────────────┘

  pool.query('SELECT...'):
  
    Lambda                              RDS PostgreSQL
       │                                     │
       │── TCP socket (10.0.1.50 → 10.0.2.20:5432)
       │                                     │
       │── PostgreSQL wire protocol:         │
       │   Query('SELECT id, email...')  ──→ │
       │                                     │ ← парсит SQL
       │                                     │ ← ищет по индексу
       │                                     │ ← находит row
       │                                     │
       │←── DataRow(1, anna@..., Anna, ...)  │
       │←── CommandComplete(SELECT 1)        │
       │                                     │
    
    Это TCP socket ВНУТРИ private subnet.
    Трафик не выходит в интернет.
    ~1-5ms latency (внутри одного AWS AZ).
```

#### Фаза 8: Ответ идёт обратно

```
Lambda                 API Gateway           CloudFront           Браузер
   │                       │                      │                   │
   │── return {            │                      │                   │
   │   statusCode: 200,    │                      │                   │
   │   body: JSON          │                      │                   │
   │  } ──────────────→    │                      │                   │
   │                       │                      │                   │
   │  (AWS internal API)   │── HTTP Response ──→  │                   │
   │                       │   200 OK             │                   │
   │                       │   { user, groups }   │                   │
   │                       │                      │── HTTP/2 ──────→  │
   │                       │                      │   Stream 5        │
   │                       │                      │   200 OK          │
   │                       │                      │   { user, groups} │
   │                       │                      │                   │


Весь путь ответа:

  PostgreSQL row
       │
       ▼
  Lambda: JSON.stringify({ user: row, groups })
       │
       ▼  (AWS Invoke response)
  API Gateway: оборачивает в HTTP response
       │
       ▼  (TCP socket: API GW → CloudFront, внутри AWS)
  CloudFront: проксирует в stream 5 на TCP #1
       │
       ▼  (TCP socket #1: CloudFront → Браузер, HTTP/2)
  Браузер: fetch() resolve → JSON.parse → setState

```
