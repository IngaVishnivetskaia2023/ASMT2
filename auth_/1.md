
```
┌─────────────────────────────────────────────────────────────────────┐
│                                                                     │
│  КТО ПРОВЕРЯЕТ ЛИЧНОСТЬ (Authentication):                          │
│                                                                     │
│  1. Ты сам         → свой сервер, своя БД с паролями               │
│  2. Облачный сервис → AWS Cognito, Firebase Auth, Auth0, Okta      │
│  3. Третья сторона  → Google, GitHub, Apple, Facebook (OAuth 2.0)  │
│  4. Корпоративный   → Active Directory, SAML, LDAP                 │
│                                                                     │
│  КАК ПОДТВЕРЖДАЕТСЯ ЛИЧНОСТЬ (механизм):                           │
│                                                                     │
│  1. Basic Auth      → логин:пароль в base64 каждый запрос          │
│  2. Session/Cookie  → сервер помнит сессию, клиент хранит cookie   │
│  3. JWT Token       → подписанный токен, сервер НЕ хранит сессию   │
│  4. API Key         → статический ключ для сервис-к-сервису        │
│  5. OAuth 2.0       → протокол делегированной авторизации          │
│  6. mTLS            → клиентские сертификаты                       │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 1. Basic Auth — самый простой (и самый старый)

```
Как работает:

  Браузер                              Сервер
     │                                    │
     │── GET /api/data ────────────────→ │
     │                                    │
     │←── 401 Unauthorized ──────────────│
     │    WWW-Authenticate: Basic        │
     │                                    │
     │  Браузер показывает встроенное    │
     │  окно ввода логин/пароль          │
     │                                    │
     │── GET /api/data ────────────────→ │
     │   Authorization: Basic YW5uYTp... │
     │                                    │── decode base64
     │                                    │── "anna:SecretPass"
     │                                    │── проверить в БД
     │                                    │
     │←── 200 OK { data }  ──────────────│


  "YW5uYTpTZWNyZXRQYXNz" = base64("anna:SecretPass")

  base64 это НЕ шифрование. Это просто кодирование.
  Любой может декодировать:
    atob("YW5uYTpTZWNyZXRQYXNz") → "anna:SecretPass"

  ⚠️  Пароль летит КАЖДЫЙ запрос.
  ⚠️  Без HTTPS — пароль видны в открытом виде.
  ⚠️  Нет logout (браузер помнит до закрытия).
  ⚠️  Нет нормального UI (уродливое встроенное окно).

  Где используется:
    ─ Внутренние API между сервисами
    ─ Простые инструменты (Jenkins, Kibana за nginx)
    ─ НЕ для пользовательских приложений
```

#### 2. Session / Cookie — классический подход

```
Как работает:

  Браузер                              Сервер                    БД
     │                                    │                       │
     │── POST /login ──────────────────→ │                       │
     │   { email, password }             │── verify password ──→ │
     │                                    │←── user found ────── │
     │                                    │                       │
     │                                    │── Создаёт SESSION:   │
     │                                    │   sessionId: "abc123" │
     │                                    │   userId: 42          │
     │                                    │   createdAt: now      │
     │                                    │── Сохраняет session──→│
     │                                    │   (в БД / Redis)      │
     │                                    │                       │
     │←── 200 OK ────────────────────────│                       │
     │   Set-Cookie: sessionId=abc123;   │                       │
     │               HttpOnly; Secure;   │                       │
     │               SameSite=Strict     │                       │
     │                                    │                      │
     │                                    │                      │
     │── GET /api/me ──────────────────→ │                       │
     │   Cookie: sessionId=abc123        │                       │
     │   (браузер шлёт автоматически!)   │                       │
     │                                    │── найти session ──→  │
     │                                    │←── userId: 42 ─────  │
     │                                    │── найти user ──────→ │
     │                                    │←── { name: Anna } ── │
     │←── 200 { name: "Anna" } ───────── │                       │
     │                                   │                       │


  Сервер ХРАНИТ состояние (stateful):
  
  Sessions table (Redis / PostgreSQL):
  ┌──────────────┬──────────┬─────────────────────┐
  │ sessionId    │ userId   │ expiresAt           │
  ├──────────────┼──────────┼─────────────────────┤
  │ abc123       │ 42       │ 2024-01-15 10:00:00 │
  │ def456       │ 17       │ 2024-01-15 11:30:00 │
  │ ghi789       │ 42       │ 2024-01-15 09:00:00 │ ← другое устройство
  └──────────────┴──────────┴─────────────────────┘


  ✅ Простой logout: удалить session из БД
  ✅ Можно "выкинуть" пользователя: удалить все его sessions
  ✅ HttpOnly cookie: JavaScript НЕ может прочитать (защита от XSS)
  
  ❌ Сервер должен хранить ВСЕ сессии
  ❌ При масштабировании: все серверы должны видеть сессии (Redis)
  ❌ CSRF атаки (cookie отправляется автоматически)

```


#### 3. JWT Token — stateless подход

```
Как работает:

  Браузер                              Сервер
     │                                    │
     │── POST /login ──────────────────→ │
     │   { email, password }             │── verify password
     │                                    │
     │                                    │── Создаёт JWT:
     │                                    │   Header: { alg: RS256 }
     │                                    │   Payload: { sub: 42, 
     │                                    │     email: anna@...,
     │                                    │     roles: ["admin"],
     │                                    │     exp: 1700003600 }
     │                                    │   Signature: sign(PRIVATE_KEY)
     │                                    │
     │←── { accessToken: "eyJ...",  ─────│
     │      refreshToken: "eyR..." }     │
     │                                    │
     │  localStorage.setItem(            │
     │    'accessToken', token)           │
     │                                    │
     │── GET /api/me ──────────────────→ │
     │   Authorization: Bearer eyJ...    │
     │                                    │── decode JWT
     │                                    │── verify signature (PUBLIC_KEY)
     │                                    │── check exp > now
     │                                    │── sub: 42 → это Anna
     │                                    │── НЕ ходит в БД за сессией!
     │                                    │
     │←── 200 { name: "Anna" } ─────────│


  Сервер НЕ хранит сессии (stateless):
  
  Вся информация ВНУТРИ токена.
  Сервер только проверяет подпись.
  
  ✅ Не нужна БД сессий / Redis
  ✅ Масштабируется: любой сервер может проверить токен
  ✅ Идеален для микросервисов и serverless (Lambda)
  
  ❌ Нельзя "отозвать" токен до exp (нет сессии которую можно удалить)
  ❌ Payload виден всем (base64, не зашифрован)
  ❌ Токен в localStorage уязвим к XSS

  
  Access Token vs Refresh Token:
  ┌─────────────────────────────────────────────────────────┐
  │                                                         │
  │  Access Token:                                         │
  │    Живёт: 15 мин — 1 час                               │
  │    Используется: в каждом API запросе                   │
  │    Компактный, содержит claims                         │
  │                                                         │
  │  Refresh Token:                                        │
  │    Живёт: дни — месяцы                                 │
  │    Используется: получить НОВЫЙ access token            │
  │    когда старый истёк                                   │
  │    Хранится безопасно (httpOnly cookie)                │
  │                                                         │
  │  Access Token истёк:                                   │
  │    POST /auth/refresh                                  │
  │    { refreshToken: "eyR..." }                          │
  │    → { accessToken: "eyJ...(новый)" }                  │
  │                                                         │
  └─────────────────────────────────────────────────────────┘
```



#### 4. OAuth 2.0 — "войти через Google/GitHub/Apple"

```
Проблема которую решает:

  Пользователь хочет войти в myapp.com.
  Но НЕ хочет создавать новый аккаунт с паролем.
  У него УЖЕ есть аккаунт Google.

  OAuth 2.0: "Пусть Google подтвердит кто ты.
              Я (myapp) не буду знать твой пароль Google."


Authorization Code Flow (самый безопасный):

  Пользователь         Браузер          myapp.com         Google
       │                   │                │                │
  1.   │── "Login with Google" ───→        │                │
       │                   │                │                │
  2.   │                   │←── redirect ───│                │
       │                   │    to Google    │                │
       │                   │                │                │
  3.   │                   │── GET /auth ───────────────────→│
       │                   │   ?client_id=myapp              │
       │                   │   &redirect_uri=myapp.com/cb    │
       │                   │   &scope=email profile          │
       │                   │   &response_type=code           │
       │                   │                                 │
  4.   │                   │←── Google login page ───────────│
       │                   │                                 │
  5.   │── email+password ─→│                                │
       │   (НА СТРАНИЦЕ     │── POST credentials ──────────→│
       │    GOOGLE!)        │                                │── verify
       │                   │                                 │
  6.   │                   │←── "Разрешить myapp доступ     │
       │── "Разрешаю" ────→│    к email и profile?"         │
       │                   │── Разрешил ───────────────────→│
       │                   │                                 │
  7.   │                   │←── 302 Redirect ────────────────│
       │                   │    myapp.com/cb                 │
       │                   │    ?code=AUTH_CODE_XYZ          │
       │                   │                 │               │
  8.   │                   │── GET /cb?code=AUTH_CODE_XYZ──→│               │
       │                   │                │               │
       │                   │                │── POST /token ────────────→│
       │                   │                │   code=AUTH_CODE_XYZ       │
       │                   │                │   client_secret=SECRET     │
       │                   │                │                            │
       │                   │                │←── { access_token,  ──────│
       │                   │                │      id_token }            │
       │                   │                │                            │
       │                   │                │── GET /userinfo ──────────→│
       │                   │                │   Bearer access_token      │
       │                   │                │←── { email, name, pic } ──│
       │                   │                │                            │
  9.   │                   │←── Set-Cookie: session=... ────│            │
       │                   │    Залогинен как Anna          │            │
       │                   │                                             │


  Ключевой момент: code обменивается на token СЕРВЕР-К-СЕРВЕРУ.
  Браузер НИКОГДА не видит client_secret.
  Браузер видит только code (одноразовый, живёт ~30 секунд).


  Implicit Flow (ваш текущий код с Cognito):
  
    Шаг 7 возвращает СРАЗУ token в URL fragment (#access_token=...).
    Нет обмена code → token.
    Проще, но менее безопасно.
    Не рекомендуется для новых приложений.
```

```
  OAuth 2.0 роли:

  ┌─────────────────────────────────────────────────────────────────┐
  │                                                                 │
  │  Resource Owner  = пользователь (Anna)                          │
  │  Client          = твоё приложение (myapp.com)                  │
  │  Authorization Server = кто проверяет пароль (Google, Cognito)  │
  │  Resource Server = кто хранит данные (Google API, твой API)     │
  │                                                                 │
  └─────────────────────────────────────────────────────────────────┘
```


#### 5. AWS Cognito — все варианты

```
Cognito = Authorization Server который поддерживает ВСЁ:

┌─── AWS Cognito ─────────────────────────────────────────────────────┐
│                                                                      │
│  ВАРИАНТ A: Hosted UI (ваш текущий код)                             │
│  ────────────────────────────────────────                            │
│                                                                      │
│  Redirect на amazoncognito.com/login                                │
│  Cognito показывает СВОЮ страницу                                   │
│  Можно кастомизировать: лого, цвета, CSS                            │
│  Пароль вводится на домене AWS                                      │
│  После логина → redirect обратно с токенами                         │
│                                                                      │
│  ✅ Безопаснее (пароль не проходит через ваш JS)                    │
│  ✅ Cognito сам делает: MFA, forgot password, sign up               │
│  ✅ Легко добавить "Login with Google/Apple/Facebook"               │
│  ❌ Ограниченная кастомизация UI                                    │
│  ❌ Пользователь видит чужой домен (amazoncognito.com)              │
│  ❌ Custom domain возможен но требует настройки                     │
│                                                                      │
│                                                                      │
│  ВАРИАНТ B: Custom UI + Cognito API (Amplify / SDK)                 │
│  ──────────────────────────────────────────────────                  │
│                                                                      │
│  React рендерит СВОЮ форму логина                                   │
│  JavaScript вызывает Cognito API напрямую (InitiateAuth)            │
│  Пароль проходит через ваш JS → fetch → Cognito                    │
│                                                                      │
│  import { signIn } from 'aws-amplify/auth';                         │
│  const result = await signIn({ username: email, password });        │
│                                                                      │
│  ✅ Полный контроль над UI                                          │
│  ✅ Пользователь не покидает сайт                                   │
│  ✅ Лучший UX                                                       │
│  ❌ Пароль проходит через ваш JavaScript                            │
│  ❌ Вы сами реализуете: MFA flow, reset password, sign up           │
│                                                                      │
│                                                                      │
│  ВАРИАНТ C: Cognito + Federated Identity (Social Login)             │
│  ──────────────────────────────────────────────────────              │
│                                                                      │
│  Cognito как ПОСРЕДНИК между вашим app и Google/Apple/Facebook      │
│                                                                      │
│  Браузер → Cognito → Google → пользователь логинится                │
│                    → Google возвращает токен Cognito                 │
│                    → Cognito создаёт/находит user                   │
│                    → Cognito возвращает СВОЙ JWT вашему app         │
│                                                                      │
│  Вы работаете только с Cognito JWT.                                 │
│  Не важно вошёл через пароль, Google или Apple.                     │
│  Один формат токена для всех.                                       │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

Сравнение вариантов A и B:

  HOSTED UI (вариант A):                CUSTOM UI (вариант B):

       │                   │                 │                    │                │

#### 7. Enterprise: SAML / SSO

```
Корпоративный мир:

  Компания "BigCorp" имеет 10,000 сотрудников.
  У каждого: Active Directory аккаунт.
  Они используют 50 разных SaaS приложений.

  БЕЗ SSO: логин в каждое приложение отдельно (50 паролей).
  С SSO:   залогинился ОДИН раз → доступ ко всем приложениям.


  SAML Flow (Security Assertion Markup Language):

  Сотрудник            myapp.com         Identity Provider
  (BigCorp)                               (Active Directory /
                                           Okta / Azure AD)
       │                   │                    │
       │── открыл myapp ─→│                    │
       │                   │── redirect ──────→│
       │                   │   SAML Request     │
       │                   │                    │
       │←── корп. логин ───────────────────────│
       │   (или уже залогинен через Windows)   │
       │                                        │
       │── credentials ───────���───────────────→│
       │                                        │── verify
       │                                        │── создать SAML Assertion
       │                                        │   (XML документ с подписью)
       │←── redirect ──────────────────────────│
       │    с SAML Assertion                    │
       │                   │                    │
       │── POST Assertion →│                    │
       │                   │── verify signature │
       │                   │── создать сессию   │
       │←── залогинен ────│                    │


  SAML Assertion (XML):
  <saml:Assertion>
    <saml:Subject>
      <saml:NameID>anna@bigcorp.com</saml:NameID>
    </saml:Subject>
    <saml:AttributeStatement>
      <saml:Attribute Name="groups">
        <saml:AttributeValue>Engineering</saml:AttributeValue>
        <saml:AttributeValue>Admins</saml:AttributeValue>
      </saml:Attribute>
    </saml:AttributeStatement>
    <ds:Signature>...</ds:Signature>
  </saml:Assertion>

  Cognito поддерживает SAML:
  BigCorp Active Directory → Cognito (SAML federation) → JWT → ваш app
```
