Fiber is React's reimplemented reconciliation engine (introduced in React 16, 2017) that enables:
- **incremental, pausable rendering** by breaking work into small units **called "fibers"**.

```

  ▼             ▼                 ▼               ▼

            thread           ✅ Prioritization    unleashed
```

#### AFTER Fiber: Fiber Reconciler (React 16+)

#### What IS a Fiber?

```
A Fiber = A JavaScript Object = A Unit of Work
════════════════════════════════════════════════

Each component/element gets its OWN fiber node:

{
  type: ComponentOrTag,      // e.g., 'div', App
  key: uniqueKey,
  stateNode: DOMNode | ComponentInstance,

  // ── TREE STRUCTURE (linked list, NOT recursion) ──
  child:   FiberNode | null,   // first child
  sibling: FiberNode | null,   // next sibling
  return:  FiberNode | null,   // parent

  // ── WORK TRACKING ──
  pendingProps: {},
  memoizedState: {},
  memoizedProps: {},

  // ── PRIORITY ──
  lanes: Lane,                 // priority bitmask

  // ── EFFECTS ──
  flags: EffectFlags,          // what DOM ops needed
  alternate: FiberNode | null  // double buffering
}
```

```
STACK RECONCILER (Tree):     FIBER (Linked List):

        <App>                   App
       /     \                  │ child
    <Nav>   <Content>          Nav ──sibling──► Content
     |       /    \             │                │ child
   <Logo> <List> <Footer>    Logo              List ──sibling──► Footer
                                                │ child
                                              Item1 ──sibling──► Item2 ──► ...

Each node knows:
  → child    (go DOWN)
  → sibling  (go RIGHT)
  → return   (go UP/BACK to parent)

This means: We can STOP at any node and RESUME later!
```


#### How Fiber Processes Work

```
TWO PHASES:
═══════════

Phase 1: RENDER / Reconciliation    Phase 2: COMMIT
(can be INTERRUPTED ⏸️)              (SYNCHRONOUS, can't stop)
                                    
┌─────────────────────────┐         ┌────────────────────────┐
│                         │         │                        │
│  Traverse fiber tree    │         │  Apply all collected   │
│  Compare old vs new     │  ──►   │  DOM mutations at once │
│  Build "effect list"    │         │  Call lifecycle methods │
│  NO DOM mutations yet!  │         │  componentDidMount     │
│                         │         │  useLayoutEffect       │
│  ⏸️ Can pause here      │         │                        │
│  🔄 Can restart here    │         │  ❌ Cannot pause!      │
│  🗑️ Can discard here    │         │                        │
└─────────────────────────┘         └────────────────────────┘
     INTERRUPTIBLE                      UNINTERRUPTIBLE
```

#### Work Loop — The Heart of Fiber

```
// Simplified Fiber Work Loop
function workLoop(deadline) {
  while (nextUnitOfWork && deadline.timeRemaining() > 0) {
    // ① Process ONE fiber node
    nextUnitOfWork = performUnitOfWork(nextUnitOfWork);
  }

  if (!nextUnitOfWork) {
    // ② All work done → COMMIT phase
    commitRoot();
  } else {
    // ③ Ran out of time → YIELD to browser
    requestIdleCallback(workLoop); // schedule remaining
  }
}
```

#### Double Buffering (Alternate Trees)

```
Fiber uses TWO trees simultaneously:

┌─────────────────┐     ┌─────────────────┐
│  CURRENT TREE   │     │ WORK-IN-PROGRESS│
│  (on screen)    │◄───►│  TREE (building) │
│                 │ alt  │                 │
│    App ●        │ern  │    App ○        │
│   /    \        │ate  │   /    \        │
│  Nav   Content  │     │  Nav   Content* │ ← changed
│  |     /    \   │     │  |     /    \   │
│ Logo List Footer│     │ Logo List* Footer│
└─────────────────┘     └─────────────────┘
                              │
                    After COMMIT phase
                              │
                              ▼
                  WIP becomes CURRENT
                  Old current becomes next WIP
                  (pointer swap — O(1))
```

#### Q: "What is Fiber in one sentence?"
A: "Fiber is a reimplementation of the call stack specialized for UI, where each stack frame is a **JS object (fiber node)** that React can schedule, pause, abort, or reuse."

#### Q: "Why couldn't they just optimize the old reconciler?"
A: "The fundamental limitation was JavaScript's call stack itself — once a recursive function starts, you can't pause it. 
Fiber replaces the implicit call stack with an explicit data structure (linked list of fiber nodes), giving React full control over execution."

#### Q: "When does the user actually FEEL the difference?"
A: "In apps with heavy UI updates — large lists, complex dashboards, animations during data loading — Fiber prevents the 'frozen UI' problem by yielding control back to the browser between units of work."
