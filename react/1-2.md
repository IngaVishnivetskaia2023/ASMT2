### React Hooks & Fiber — The Deep Connection

Hooks are **stored as a linked list** on the fiber node's `memoizedState` property. 
**Each hook call creates a node in that list** — this is WHY hooks must be called in the same order every render.

```
┌──────────────────────────────────────────────┐
│                FIBER NODE                     │
│                                              │
│  {                                           │
│    type: MyComponent,                        │
│    stateNode: ...,                           │
│    memoizedState: ──────►  Hook 1 (useState) │
│    updateQueue: ...,         │ .next         │
│    flags: ...,             Hook 2 (useEffect)│
│    lanes: ...,               │ .next         │
│    alternate: ...,         Hook 3 (useMemo)  │
│  }                           │ .next         │
│                            Hook 4 (useRef)   │
│                              │ .next         │
│                             null             │
└──────────────────────────────────────────────┘

Every functional component instance = 1 Fiber Node
Every hook call = 1 node in that fiber's hook linked list
```

#### Hook Object Structure

```
Each hook in the linked list is an object:

┌─────────────────────────────────────┐
│          HOOK OBJECT                │
│                                     │
│  {                                  │
│    memoizedState: any,  ← stored value    
│    baseState: any,      ← base for updates
│    baseQueue: Update | null,              
│    queue: {             ← pending updates  
│      pending: null,                  
│      dispatch: fn,      ← setState fn     
│      lastRenderedReducer: fn,        
│      lastRenderedState: any          
│    },                                
│    next: Hook | null    ← next hook ──►   
│  }                                  │
└─────────────────────────────────────┘
```

#### What Each Hook Stores in memoizedState

```
┌──────────────────┬──────────────────────────────────────┐
│  HOOK            │  memoizedState contains               │
├──────────────────┼──────────────────────────────────────┤
│ useState         │ Current state value                   │
│                  │ e.g., 0, "hello", [1,2,3]            │
├──────────────────┼──────────────────────────────────────┤
│ useReducer       │ Current reducer state                 │
├──────────────────┼──────────────────────────────────────┤
│ useEffect        │ Effect object:                        │
│                  │ { tag, create, destroy, deps, next }  │
├──────────────────┼──────────────────────────────────────┤
│ useRef           │ { current: value }                    │
│                  │ (same object ref persists)            │
├──────────────────┼──────────────────────────────────────┤
│ useMemo          │ [computedValue, deps]                 │
├──────────────────┼──────────────────────────────────────┤
│ useCallback      │ [callback, deps]                      │
├──────────────────┼──────────────────────────────────────┤
│ useContext        │ (reads from fiber tree, no local     │
│                  │  memoizedState used)                  │
├──────────────────┼──────────────────────────────────────┤
│ useTransition    │ [isPending, startTransition]          │
└──────────────────┴──────────────────────────────────────┘
```

### Real Example — How It Maps

```
function UserProfile({ id }) {
  const [name, setName] = useState("Alice");     // Hook 1
  const [age, setAge] = useState(25);             // Hook 2
  const prevId = useRef(null);                     // Hook 3
  
  useEffect(() => {                                // Hook 4
    fetchUser(id);
  }, [id]);
  
  const display = useMemo(                         // Hook 5
    () => `${name} (${age})`, 
    [name, age]
  );
  
  return <div>{display}</div>;
}
```

#### Mount vs Update — Two Dispatchers
```
React internally switches the "dispatcher" based on phase:

┌─────────────────────────────────────────────────────┐
│                                                     │
│   MOUNT (first render)        UPDATE (re-render)    │
│   ═══════════════════        ═══════════════════    │
│                                                     │
│   HooksDispatcherOnMount     HooksDispatcherOnUpdate│
│                                                     │
│   useState → mountState()    useState → updateState()
│   useEffect→ mountEffect()   useEffect→ updateEffect()
│   useRef  → mountRef()       useRef  → updateRef()  │
│   useMemo → mountMemo()      useMemo → updateMemo() │
│                                                     │
│   Creates NEW hook nodes     TRAVERSES existing     │
│   Builds linked list         linked list             │
│   from scratch               reads by POSITION      │
│                                                     │
└─────────────────────────────────────────────────────┘

      ReactCurrentDispatcher.current = ???
              │
      ┌───────┴────────┐
      ▼                ▼
   On Mount         On Update
   (create)         (traverse)
```

```
MOUNT Phase — Building the list:
═════════════════════════════════

useState("Alice") → CREATE Hook1 → list: H1
useState(25)      → CREATE Hook2 → list: H1 → H2
useRef(null)      → CREATE Hook3 → list: H1 → H2 → H3
useEffect(...)    → CREATE Hook4 → list: H1 → H2 → H3 → H4
useMemo(...)      → CREATE Hook5 → list: H1 → H2 → H3 → H4 → H5

UPDATE Phase — Reading the list:
═════════════════════════════════

                    cursor
                      │
                      ▼
                     [H1] → [H2] → [H3] → [H4] → [H5]

useState("Alice") → READ H1, cursor moves ──►
useState(25)      → READ H2, cursor moves ──────►
useRef(null)      → READ H3, cursor moves ──────────►
useEffect(...)    → READ H4, cursor moves ──────────────►
useMemo(...)      → READ H5, cursor moves ──────────────────► done
```

### WHY Hooks Can't Be Conditional

```
// ❌ BROKEN
function Bad({ showName }) {
  if (showName) {
    const [name, setName] = useState("Alice");  // Hook 1 (maybe)
  }
  const [age, setAge] = useState(25);            // Hook 2 (or 1?)
  useEffect(() => { ... }, []);                   // Hook 3 (or 2?)
}
```

```
✅ CORRECT                          ❌ INCORRECT
═══════════                         ═════════════

Every render:                       Render 1:        Render 2:
                                    
H1 → H2 → H3 → H4                 H1 → H2 → H3    H1 → H2
│     │     │     │                 │     │     │    │     │
same  same  same  same              ok    ok   ok   💥    💥
hook  hook  hook  hook              
call  call  call  call              LENGTH MISMATCH = CRASH
                                    POSITION MISMATCH = CORRUPTION
```


#### `useState` Update Flow Through Fiber

```
setName("Bob") is called:
═══════════════════════════

Step 1: Dispatch
───────────────────────────────────
  setName("Bob")
       │
       ▼
  Create UPDATE object: { action: "Bob", lane: SyncLane }
       │
       ▼
  Enqueue on Hook1's queue:
  hook1.queue.pending = update
       │
       ▼
  Schedule re-render on this Fiber
  markUpdateLaneFromFiberToRoot(fiber, lane)


Step 2: Re-render (Render Phase)
───────────────────────────────────
  React calls UserProfile() again
       │
       ▼
  Dispatcher = HooksDispatcherOnUpdate
       │
       ▼
  useState hit → updateReducer()
       │
       ▼
  Process queued updates:
  ┌────────────────────────────────────┐
  │  baseState: "Alice"                │
  │  + update { action: "Bob" }        │
  │  = newState: "Bob"                 │
  │                                    │
  │  hook1.memoizedState = "Bob"       │
  └────────────────────────────────────┘
       │
       ▼
  Component returns new JSX with "Bob"


Step 3: Commit Phase
───────────────────────────────────
  Diff old fiber ↔ new fiber
  Apply DOM mutations
  User sees "Bob" on screen ✅
```

#### Effects & Fiber — The Effect List

```
During RENDER phase, effects are collected:

Fiber Node
│
├── updateQueue ──► Effect Circular Linked List
│
│   ┌────────┐    ┌────────┐    ┌────────┐
│   │Effect 1│───►│Effect 2│───►│Effect 3│───┐
│   │useEffect│   │useLayout│   │useEffect│   │
│   │        │◄───┴────────┴────┴────────┘   │
│   └────────┘◄──────────────────────────────┘
│     (circular)

During COMMIT phase, React processes effects:

┌─────────────────────────────────────────────────┐
│                                                 │
│  Before Mutation    Mutation      After Mutation │
│  ───────────────    ────────     ──────────────  │
│                                                 │
│  getSnapshot        DOM writes   useLayoutEffect │
│  (useLayoutEffect   (insert,     (sync, blocks  │
│   cleanup runs)     update,      paint)          │
│                     delete)                      │
│                                  useEffect       │
│                                  (async, after   │
│                                   paint via      │
│                                   scheduler)     │
│                                                 │
└─────────────────────────────────────────────────┘
```

```
Timeline:

──── RENDER ────|──── COMMIT ────────────────|── BROWSER ──

  Build fiber    │  Cleanup     DOM      Layout │  Paint
  tree &         │  prev        write    effects│  
  collect        │  layout               fire   │  useEffect
  effects        │  effects                     │  fires HERE
                 │                               │  (async)
                 │  ◄── synchronous ──►         │
                                                │
                                          requestIdleCallback
                                          or MessageChannel
```

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  Q: "Why are hooks tied to fiber?"                       │
│  A: "Fiber IS the persistent identity of a component    │
│      instance. Since functional components have no       │
│      `this`, fiber's memoizedState IS the instance       │
│      state — hooks are just a linked list hanging        │
│      off that property."                                 │
│                                                          │
│  Q: "Why linked list and not array?"                     │
│  A: "Linked lists allow O(1) append during mount         │
│      and efficient traversal. No resizing. Each hook     │
│      node can also hold its own update queue as          │
│      a circular linked list for batched updates."        │
│                                                          │
│  Q: "What happens if I call hooks in a loop?"            │
│  A: "If the loop count changes between renders,          │
│      the cursor misaligns with the stored linked list    │
│      — React reads wrong memoizedState for wrong hook.   │
│      That's why the ESLint rules-of-hooks plugin         │
│      exists."                                            │
│                                                          │
│  Q: "How does React know which fiber a hook belongs to?" │
│  A: "React sets a global variable                        │
│      `currentlyRenderingFiber` before calling your       │
│      component function. All hook calls during that      │
│      execution read/write to THAT fiber's hook list."    │
│                                                          │
└──────────────────────────────────────────────────────────┘
```
