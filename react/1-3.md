`MessageChannel` is a browser API that creates a **two-port communication channel** where messages are delivered **as macrotasks**, 
enabling async communication between different execution contexts (or even within the same context for scheduling purposes).

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│              MESSAGE CHANNEL                        │
│                                                     │
│   ┌─────────┐    Invisible Pipe    ┌─────────┐     │
│   │         │ ◄══════════════════► │         │     │
│   │  Port1  │                      │  Port2  │     │
│   │         │                      │         │     │
│   └────┬────┘                      └────┬────┘     │
│        │                                │          │
│   .onmessage                       .postMessage    │
│   (receive)                        (send)          │
│                                                    │
│        OR vice versa — both ports can send/receive │
│                                                    │
└─────────────────────────────────────────────────────┘

const channel = new MessageChannel();

channel.port1.onmessage = (event) => {
  console.log("Received:", event.data);
};

channel.port2.postMessage("Hello!");
// logs: "Received: Hello!"
```

#### Where Does It Sit in the Event Loop?

```
EVENT LOOP PRIORITY ORDER:
══════════════════════════

  ┌──────────────────────────────────────────────────┐
  │                                                  │
  │  1. CURRENT MACROTASK (synchronous code)         │
  │     └── script, setTimeout callback, click, etc  │
  │                          │                       │
  │                          ▼                       │
  │  2. ALL MICROTASKS (drain entire queue)           │
  │     └── Promises, queueMicrotask,                │
  │         MutationObserver                         │
  │                          │                       │
  │                          ▼                       │
  │  3. RENDERING (if needed, ~60fps)                │
  │     └── rAF → Style → Layout → Paint            │
  │                          │                       │
  │                          ▼                       │
  │  4. NEXT MACROTASK (one from queue)              │
  │     └── ⭐ MessageChannel fires HERE             │
  │     └── setTimeout / setInterval                 │
  │     └── I/O callbacks                            │
  │                                                  │
  └──────────────────────────────────────────────────┘

KEY INSIGHT:
═══════════
  MessageChannel creates a macrotask with:
  ✅ NO minimum delay (unlike setTimeout's ~4ms)
  ✅ IMMEDIATE queue entry
  ✅ Fires ASAP after microtasks + optional render
```

#### MessageChannel vs setTimeout

```
console.log("1: sync");

setTimeout(() => console.log("4: setTimeout"), 0);

const ch = new MessageChannel();
ch.port1.onmessage = () => console.log("3: MessageChannel");
ch.port2.postMessage("");

Promise.resolve().then(() => console.log("2: microtask"));

// OUTPUT ORDER:
// 1: sync          ← current task
// 2: microtask     ← microtask queue
// 3: MessageChannel ← macrotask (NO delay)
// 4: setTimeout    ← macrotask (~4ms delay)
```

```
Timeline:

0ms        0ms         ~0ms          ~4ms
│          │            │              │
▼          ▼            ▼              ▼
sync    Promise   MessageChannel   setTimeout
code    .then()   .onmessage       callback

         micro      macro            macro
         task       task             task
                    (instant)        (min ~4ms delay)
```

#### Web Workers Communication

```
┌──────────────────┐          ┌──────────────────┐
│   MAIN THREAD    │          │   WEB WORKER     │
│                  │          │                  │
│  const worker =  │          │                  │
│   new Worker()   │          │                  │
│                  │          │                  │
│  // Option A: basic postMessage               │
│  worker.postMessage(data)──►│ onmessage       │
│                  │          │                  │
│  // Option B: Transfer a MessagePort          │
│  const ch =      │          │                  │
│   new Message    │          │                  │
│    Channel();    │          │                  │
│                  │          │                  │
│  ch.port1        │          │                  │
│   .onmessage = ◄─────────────.postMessage     │
│    handler;      │          │  (via port2)     │
│                  │          │                  │
│  worker          │          │                  │
│   .postMessage(  │          │                  │
│    {port:        │          │                  │
│     ch.port2},   │          │                  │
│    [ch.port2])───┼─────────►│ receives port2   │
│   (transferred!) │          │ owns it now      │
│                  │          │                  │
└──────────────────┘          └──────────────────┘

WHY not just `worker.postMessage`?
  → MessageChannel allows MULTIPLE independent
    communication channels to same worker
  → Each channel = separate concern
```

```
// Real example: Image processing worker with multiple channels

const commandChannel = new MessageChannel();
const dataChannel = new MessageChannel();

// Channel 1: Commands (start, stop, configure)
commandChannel.port1.onmessage = (e) => {
  console.log("Command response:", e.data);
};

// Channel 2: Heavy data streaming
dataChannel.port1.onmessage = (e) => {
  console.log("Processed image chunk:", e.data);
};

worker.postMessage(
  { commandPort: commandChannel.port2, dataPort: dataChannel.port2 },
  [commandChannel.port2, dataChannel.port2]  // Transfer ownership
);
```

#### Cross-iframe Communication

```
┌──────────────────────────────────────────────────────┐
│  PARENT PAGE (app.example.com)                       │
│                                                      │
│  ┌────────────────────────────────────────────────┐  │
│  │                                                │  │
│  │  const channel = new MessageChannel();         │  │
│  │                                                │  │
│  │  channel.port1.onmessage = (e) => {            │  │
│  │    console.log("From iframe:", e.data);        │  │
│  │  };                                            │  │
│  │                                                │  │
│  │  iframe.contentWindow.postMessage(             │  │
│  │    "init",                                     │  │
│  │    "https://widget.example.com",               │  │
│  │    [channel.port2]  // transfer port2          │  │
│  │  );                                            │  │
│  │                                                │  │
│  │  ┌──────────────────────────────────────────┐  │  │
│  │  │  IFRAME (widget.example.com)             │  │  │
│  │  │                                          │  │  │
│  │  │  window.onmessage = (e) => {             │  │  │
│  │  │    const port = e.ports[0];              │  │  │
│  │  │    port.postMessage("Hello parent!");    │  │  │
│  │  │                                          │  │  │
│  │  │    // Now have DIRECT channel            │  │  │
│  │  │    // No more origin checks needed       │  │  │
│  │  │    // for subsequent messages            │  │  │
│  │  │  };                                      │  │  │
│  │  └──────────────────────────────────────────┘  │  │
│  └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘

WHY MessageChannel over window.postMessage?
  ✅ Direct connection — no broadcast to all listeners
  ✅ More secure — port is private between two parties
  ✅ No need to check event.origin on every message
  ✅ Multiple independent channels possible
```

#### Microtask-Free Scheduling (Polyfill for `setImmediate`)

```
// When you need async execution WITHOUT delay
// but also WITHOUT blocking microtask queue

function createImmediateScheduler() {
  const queue = [];
  const channel = new MessageChannel();

  channel.port1.onmessage = () => {
    const task = queue.shift();
    if (task) task();
  };

  return function scheduleImmediate(callback) {
    queue.push(callback);
    channel.port2.postMessage(null);
  };
}

const runImmediate = createImmediateScheduler();

// Use it:
runImmediate(() => console.log("Runs ASAP, as macrotask"));
```

│                        │                              │

│                        │                              │

│                        │                              │

│ requestIdleCallback    │ Unpredictable timing         │
│                        │                              │
